# 路线图

每个阶段都要有**可验收的产出**，否则很容易变成"看了很多资料但什么都没跑起来"。

## 阶段 0 · 环境

- [ ] 拿到板子，确认型号、供电、调试接口（SWD）
- [ ] 装 STM32CubeIDE / STM32CubeProgrammer，跑通点灯
- [ ] 装 ST Edge AI（原 STM32Cube.AI），跑通官方示例
- [ ] 记录：工具版本、烧录命令、驱动踩坑

**验收**：能用官方示例把一张图跑出分类结果。

## 阶段 1 · 基线

- [ ] 选一个公开数据集（先别自己标数据）
- [ ] 在 PC 上训练一个 YOLO，记录 mAP
- [ ] 固定输入分辨率、类别数、评测脚本
- [ ] 把模型导出成 ONNX

**验收**：PC 上能复现出 mAP，且导出过程可重跑。

## 阶段 2 · 量化

- [ ] 用代表性数据集做 INT8 量化
- [ ] 对比 FP32 与 INT8 的 mAP 差距
- [ ] 记录量化前后的模型大小

**验收**：精度损失在可接受范围内，且知道损失主要来自哪一层。

## 阶段 3 · 部署

- [ ] 模型转成 ST 的中间格式
- [ ] 生成 C 代码 / 二进制，接入固件
- [ ] 用静态图跑通一次推理
- [ ] 用摄像头或图片序列跑通

**验收**：板子上能对一张图输出正确的框。

## 阶段 4 · 实测

- [ ] 帧率（含预处理、推理、后处理）
- [ ] 内存占用（权重、激活、堆栈）
- [ ] 功耗（运行态、空闲态）

**验收**：有一张表，能说清时间花在哪。

## 阶段 5 · 优化

- [ ] 降低输入分辨率，看精度与帧率的取舍
- [ ] 后处理（NMS）搬到 MCU 上的开销
- [ ] 双缓冲 / DMA，减少等待

**验收**：相比阶段 4 有可量化的提升，且记录了代价。

## 风险与预设

- **内存不够**：STM32N6 的 NPU 有独立内存，但激活和中间结果仍要精打细算
- **量化掉点**：小模型对量化更敏感，可能要先换更简单的 backbone
- **工具链版本**：ST 的工具更新快，教程和实际界面对不上是常态，以官方 release note 为准
