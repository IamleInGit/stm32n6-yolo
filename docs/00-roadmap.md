## 阶段 2 · 量化 ✅ 本地方案成立，板端待验

> INT8 QDQ 找到零体积代价的配方：**只排除检测头里 24 个无权重解码节点**，
> 体积 12.04 → **3.34 MB**（27.7%），mAP50 0.575 → **0.547**（预训练模型 0.393 → 0.390）。
> 全量量化会掉到 0.367，整个头留 float 则涨到 5.79 MB——都不如这个方案。
> 详见 [`05-quantization.md`](05-quantization.md)。

- [x] 用代表性数据集做 INT8 量化 —— 61 张校准，QDQ + per-channel
- [x] 对比 FP32 与 INT8 的 mAP 差距 —— 全量 0.367；只排解码节点 **0.547**
- [x] 记录量化前后的模型大小 —— 12.04 → 3.34 MB
- [x] **查清损失来源 —— 检测头的 anchor 解码 + DFL 路径（24 个零参数节点）**
- [ ] 用 STEdgeAI 的 `onnx_quantizer` 复核，并验证能否在卷积头处截断（解码交给 C 代码）
- [ ] 换更大数据集重训（COCO 官方源 46 KB/s，需另找镜像）

**验收**：精度损失在可接受范围内，且知道损失主要来自哪一层。

## 风险与预设

- **内存不够**：STM32N6 的 NPU 有独立内存，但激活和中间结果仍要精打细算
- **量化掉点**：小模型对量化更敏感，可能要先换更简单的 backbone
- **工具链版本**：ST 的工具更新快，教程和实际界面对不上是常态，以官方 release note 为准
