# 术语入门：算子、量化与整个框架

> 写给有嵌入式背景、但没碰过神经网络部署的人。
> 目标：读完能用自己的话解释「算子」「量化」「算子融合」「fallback」，并且知道它们在自己的项目里出现在哪。

---

## 0 先把名词映射成你熟悉的东西

| 术语 | 一句话 | 嵌入式里的对应物 |
| :--- | :--- | :--- |
| **算子**（operator） | 计算图上的一个节点 = 一个函数 | 一条封装好的驱动函数，比如 `ADC_Start_DMA()`——调一次，它干一堆事 |
| **计算图**（graph） | 节点 + 数据流构成的有向图 | 你的数据流：`ADC → DMA → FFT → UART`，只是节点换成了"卷积""池化" |
| **张量**（tensor） | 多维数组 + shape | `buffer` + 维度描述；`[1,3,224,224]` = 1 张、3 通道、224×224 |
| **量化**（quantization） | float → int8 的定点化 | **就是 Q 格式**；你写过 Q15，这就是 Q7 的批量版 |
| **scale / zero_point** | 码值与实值的换算关系 | `Vref/4096` 加零点偏移；`float = (int8 - zp) * scale`，和 ADC 码值转电压同构 |
| **算子融合**（fusion） | Conv+BN+激活 合成一个算子 | 把三次搬运合并成一条 DMA 链，省两次读写 |
| **fallback** | 硬件没有这条指令，用软件模拟 | 没有 FPU 时的软浮点——能跑，但慢几十倍 |

**关键一句**：NPU 本质是「一堆 MAC + 片上缓存 + 指令队列」。它不是通用 CPU，只认固定几种数据流模式。所以"算子能不能上 NPU"，等价于"这条指令在不在它的指令集里"。

## 1 算子：从一条指令到一层网络

一条卷积算子在做的事，你已经会：

```
for each 输出位置:
    sum = 0
    for each kernel 位置:
        sum += input[...] * weight[...]
    output[...] = activate(sum + bias)
```

差别只在于规模：一次要算 224×224×32 个点，每个点几十次乘加。

模型里的一"层"，通常就是一个算子（或几个算子的融合体）：

| 模型里的名字 | 实际是什么算子 |
| :--- | :--- |
| Conv | 卷积（最耗算力） |
| BN | 逐元素缩放 + 平移 |
| SiLU | `x * sigmoid(x)`，查表或近似 |
| Concat | 内存拼接 |
| Resize/Upsample | 插值放大 |
| Softmax（DFL 里） | 指数 + 归一化 |

把这些算子按顺序连起来，就是**计算图**。你导出的 `best.onnx`，本质就是这张图的一份序列化。

## 2 量化：Q 格式的批量版

### 2.1 公式

量化（float → int8）：

```
q = round(x / scale) + zero_point      // 存进 int8
```

反量化（int8 → float）：

```
x = (q - zero_point) * scale
```

和你把 ADC 码值转电压是同一件事：

```
voltage = code * (Vref / 4096)         // scale = Vref/4096
```

`zero_point` 的作用是让 0 能被精确表示（对应 ADC 的零点偏移）。

### 2.2 per-tensor 与 per-channel

| 方式 | 含义 | 类比 |
| :--- | :--- | :--- |
| per-tensor | 整个张量共用一个 scale | 全板共用一个量程 |
| **per-channel** | 每个输出通道一个 scale | 每个通道单独标定 |

神经网络里各通道的数值范围差异很大，共用量程会大量截断，所以**部署默认用 per-channel**——这也是为什么导出时要改 `quant_type`。

### 2.3 为什么会掉点

量化误差不是均匀的，两类地方最敏感：

1. **分辨率不够**：int8 只有 256 级，表示 0~1 的 softmax 输出，分辨率只有 1/256
2. **非线性放大误差**：`exp()` 会把输入的微小误差放大；softmax 之后再量化，误差进一步累积

这解释了一个具体现象：YOLOv8 的检测头里有 anchor 解码（乘除）和 DFL（softmax），这两段对 int8 极不友好，量化后框的位置会漂。本项目的处理办法是**把这段解码排除在量化之外，留给 CPU 用 float 算**——代价是这部分算得慢一点，但结果是 24 个零权重节点，不增加体积。

## 3 算子融合与 fallback

### 3.1 融合

Conv → BN → SiLU 三个算子可以合并成一次计算：

```
y = SiLU( (x*W + b - mean)/std * gamma + beta )
```

编译器会把常量折进去，生成一个算子。收益是**少两次内存往返**——在 MCU 上，内存带宽常常比算力更紧。

### 3.2 fallback

NPU 的指令集有限。遇到不支持的算子（比如某些动态 shape、某些 attention），编译器只能把它切给 Cortex-M55 用软件算：

```
NPU 支持的层  → 生成 NPU 指令      （快，微秒级）
NPU 不支持的  → 生成 C 代码给 CPU  （慢，毫秒级，差 10~100 倍）
```

看编译报告里 fallback 的占比，就知道这个模型"是不是真的跑在 NPU 上"。

## 4 十分钟看穿：用 Netron 打开你的模型

1. 打开 <https://netron.app/>（在线版，不用装）
2. 拖入 `best_int8_nonconv.onnx`
3. 你会看到一张有几百个方框的图——**每个方框就是一个算子**
4. 点任意方框，右侧显示：输入输出 shape、数据类型、**量化参数（scale / zero_point）**

三个立刻能看出来的东西：

- 哪些节点带量化参数，哪些不带（对应"只排 24 个节点"的方案）
- 检测头那一段的算子构成（Conv → Reshape → Softmax/DFL → Concat）
- 张量从 `[1,3,224,224]` 变成 `[1,5,1029]` 的完整路径

**这十分钟的直观程度，超过读十篇文章。**

## 8 一句话总结

> **模型是一张图，算子是图上的节点，量化是把 float 换成 Q 格式，NPU 是只认部分节点的加速器，fallback 就是它不认的那部分回落给 CPU。**

记住这句话，再看任何部署文档都不会发懵。
